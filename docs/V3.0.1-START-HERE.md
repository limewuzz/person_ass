## 这一版做了什么

v3.0 的源码身份、契约锁、测试与 CI 记录都自洽，本包没有重做任何已成立的部分。新增的是**它第一次被真正部署起来时暴露的两类问题**，以及部署本身的完整可复现记录。

**修复 1：UIBootstrap 报告的契约版本过期。** `backend/queries.py` 写死 `1.1.1-local-integrated`，穿越 2.0/3.0 两次迁移未动，且回归测试把错值当断言，所以永远是绿的。同一个服务里 `clients_sync` 报的却是正确的 `3.0.0-fanout-local`，两个端点互相矛盾。已连测试、Mock fixture、契约校验基线一起修正。

**修复 2：新版 npm 下 `npm ci` 后构建静默失败。** npm ≥ 11.19 默认拦截 postinstall，`esbuild` 平台二进制装不上，`vite build` 报错但不指向根因。CI 固定 Node 24 自带的旧 npm，所以 CI 看不见。已在 `package.json` 补 `allowScripts`。

**新增：单机部署运行手册。** systemd 单元、nginx 反代配置，以及两个必须知道的反代约束——应用同时校验 `Host` 与 `Origin` 必须精确为 `127.0.0.1:5174`，反代不重写这两个头一律 403；SSE 必须关 buffering。

## 一个必须先读的事实

`POST /local/session` **不校验任何凭据**，只需 `Origin` 头匹配即返回 admin（8 scope）。这是 LOCAL_MOCK 的设计前提，不是缺陷，但它意味着：

> 端口 5174 绝不能直接暴露到公网。

本包的公网方案因此是「应用保持 loopback → nginx 前置 Basic Auth + TLS」，而不是把应用绑到 `0.0.0.0`。

## 恢复与启动

```sh
tar -xzf source.tar.gz && cd source
python3 -m venv .venv && .venv/bin/pip install -q -r backend/requirements.lock
npm ci --prefix frontend
export MW_PYTHON="$PWD/.venv/bin/python"
node scripts/mw.mjs contract && node scripts/mw.mjs build
node scripts/mw.mjs start --static      # http://127.0.0.1:5174
```

常驻化与公网暴露见 `docs/V3.0.1-DEPLOYMENT.md` 第 4、5 节。

## 四项未修问题（需你决策）

1. **fanout 在部署态不会自动推进**：合成 worker 只领 `local.simulate`，不消费 outbox；worker JWT 由进程内随机密钥签发，外部无法自签。建议加本地 evolver 开关，生产路径不变。
2. **`FanoutCreate.targets` 实为 step_id**：契约无 enum 无描述，传平台名返回 400。修它要改契约 SHA，属 breaking 流程。
3. **公网面无速率限制**：单一共享口令，无失败锁定。
4. **自签证书无信任链**：有域名可切 Let's Encrypt。
